## P2-2  stableTimers 内存泄漏（extension/content.js）

**问题**：定时器回调执行后从不删除 stableTimers 里的 key；且 key 由 block.id + 文本指纹
拼成，文本一变 key 就变，导致 key 无限堆积（内存泄漏）。回调提前 return 的路径同样不删。

**修法**：在回调函数体第一行无条件 delete stableTimers[fp];（位于所有 return 之前）。

**为何无条件删安全**：每次重排同一 fp 都先 clearTimeout 再赋新句柄，能真正触发的只有最后一次调度
的定时器，delete 时它必然指向自己，不会误删“新一代”的定时器。

**证据**：

- content.js:634  =  delete stableTimers[fp];  （clearTimeout 在 632、setTimeout 在 633，delete 在 634 首行）
- manifest.json:46  =  "version": "0.5.12"

**生效前提**：扩展代码改动，必须在 chrome://extensions 重载扩展；卡片版本号是唯一可靠信号。
已重载，版本显示 0.5.12。

## P2-1  host.py Popen cwd 不可控（native-host/host.py）

**问题**：subprocess.Popen 未传 cwd，命令工作目录继承 host 进程 cwd，不可预测、不可控。

**修法**：新增模块级常量 HOST_CWD = os.path.expanduser("~")（host.py:26），
Popen 显式传 cwd=HOST_CWD（host.py:188-189）。注释用英文（规避 CHCP 编码风险）。

**证据**：

- host.py:26   HOST_CWD = os.path.expanduser("~")  # fixed cwd: predictable, idempotent
- host.py:189  cwd=HOST_CWD,
- python ast.parse 语法自检通过。
- 运行实锤：发探针块，(Get-Location).Path 与 USERPROFILE 均返回 C:\Users\Achilles，确认命令在 home 下执行。

**生效前提**：host.py 改动需重启 host（完全退出 Chrome 再开）。已重启并验证。
