| 读者 | 机制 | 可靠性 |

### 7.2 问题一：三个扩展 ID 并存怎么处理

**现状**

| ID | 值 | 由谁定 | 用在哪 |
|---|---|---|---|
| 开发/解压加载 | `aaemlgedddakpgkfoakfmkdiiheplgnl` | 仓库 `manifest.json` 的 `key`（`extension/manifest.json:33`） | 白名单第 1 项 |
| Chrome 商店 | `pboakanoekehbongkmaeianbkebpfahl` | CWS 首次上传分配 | 白名单第 2 项（`install.py:23-26`） |
| Edge 商店 | 待分配 | Edge 首次上传分配 | 尚未加入 |

**机制**：ID = 公钥 DER 的 SHA256 前 32 位 hex → `0-f` 映射到 `a-p`。
解压加载按目录路径哈希生成（换路径就换 ID），故必须用 `key` 钉死；
商店上传时 `build.sh:22-30` 剥掉 `key`，商店自己生成密钥对 → 必然是新 ID；
两个商店各自生成 → 两个商店 ID 必然不同。

**Chrome 商店 ID 与 Edge 商店 ID 能否相同：按现有资料不能，应预期不同。**

- Microsoft 社区答复：Edge 的 ID 上传后即固定、无法更改，且上传含 `key` 字段的包会被拒；
  有开发者反馈照 `.pem` / `key` 那套做**仍然失败**。
- 2026 年 MV3 发布指南直接下结论：*"The published extension gets an Edge-specific
  extension id, different from the Chrome Web Store id … Same package, separate store,
  separate id."*
- 但仍**值得花一次上传实测**：Edge 首次上传时带上 `key`，看它是否保留指定 ID。
  保留 → 全项目只剩 1 个 ID；忽略（大概率）→ 按 2 个商店 ID 走。成本 = 一次尝试。

**推荐：3 个压成 2 个 —— 让「仓库解压加载的 ID」= 「Chrome 商店 ID」**

步骤（公开文档里的标准套路）：

1. Chrome 里装好已上架的商店版
2. 打开 `%LOCALAPPDATA%\Google\Chrome\User Data\Default\Extensions\pboakanoekehbongkmaeianbkebpfahl\<版本>\manifest.json`
3. 抄出里面的 `key` 值（商店安装时 Chrome 会把公钥写进已安装的 manifest）
4. 粘进仓库 `extension/manifest.json` 的 `key` 字段（替换 `aaeml...`）
5. 重新加载解压扩展 → ID 变成 `pboak...`，与商店版一致

`build.sh` **继续剥 key 不变** → 上传包与今天完全一样 → 对已上架商店项**零风险**。

**为什么这比保持 3 个 ID 好（不只是省一个常量）**

`chrome.storage.local` 是按**扩展 ID 分区**的，而扩展持久化了这些：

| 键 | 用途 | 代码位置 |
|---|---|---|
| `mh_processed` | **已执行过的块 id 列表（保留最近 300 个）** | `content.js:265-272` |
| `mh_machine_id` | 本机 UUID 缓存 | `background.js:140` |
| `mh_local_hostname` / `mh_platform` | 握手缓存 | `background.js:138,143` |
| `mh_auto_send` | 自动发送开关 | `popup.js:14` |

开发 ID ≠ 商店 ID ⇒ 这四样是**两个完全独立的储物柜**。真实后果：
**从开发版切到商店版（或反向），`mh_processed` 归零 → 聊天里的老命令块被当成新块重新执行一遍。**
这正是 `processed` 存在的唯一目的。合并 ID 不只是省条目，是消掉一整类
「切换版本才发作的重复执行」bug，并让本地开发即在验证商店路径。

代价：同一浏览器 profile 不能同时装开发版和商店版（Chrome 视为同一扩展）。
要测商店版就禁用开发版，代价可接受。

**硬约束（决定了排期）**：manifest 由 `install.py:118-145` 生成、落在用户机器上，
native messaging 只读磁盘上那个 manifest ⇒ **任何新增 ID 都必然要求用户重跑一次
`install.py`**，做不到「加了 ID 自动生效」（§一 与 `store/checklist.md:29-36` 的
After going live 流程就是这个约束的体现）。既然躲不掉，就应在 **Edge 首发前把 ID
集合一次定死**，别让用户重装两轮。

**配套建议**

- 白名单数据源化：`install.py:23-26` 的硬编码改成读 `native-host/extension_ids.json`；
  单行安装模式复用已有的 `install.py:74-85` `_working_base()` GitHub/Gitee 镜像兜底。
  加商店 = 改一行数据，不碰代码。
- `install.py:173-178` 的提示语补一句「重装后需重启浏览器」，理由见 §7.3 ④。

### 7.3 问题二：Chrome 与 Edge 共用 `~/.webai-hands`，会出问题

> 先纠正：用户记忆里的 `~/.webai-host` **不存在**，全仓无此字符串；
> 实际安装目录是 `~/.webai-hands`（`install.py:35`），Windows 为 `C:\Users\<用户>\.webai-hands`。

**结论：会，而且不是理论风险 —— 只要用户同时开着两个浏览器的 AI 页面就会命中。**

根因一句话：**native messaging 每个浏览器各起一个常驻 host 进程，两个进程之间没有任何
互斥，却在读写同一批状态文件。** DESIGN §6.1 把「本地 host」写成单数，实际部署里是复数。

#### ① `exec_history.json` 全量覆盖 → 去重记录被抹掉，甚至整份损坏（严重）

```
host.py:387      HISTORY = load_history()      # 启动时读一次，之后只改内存
host.py:266      HISTORY[rid] = {...}
host.py:276      save_history(HISTORY)         # 每次执行后【整文件重写】
host.py:104-116  save_history: open(path,"w")  # 覆盖写
```

- Chrome 执行 id=A → 写 `{A}`；Edge 执行 id=B → 它的内存里**没有 A** → 写 `{B}`
  → **A 的记录被静默抹掉**。
- 这不是丢日志，是**破坏幂等去重**：`host.py:177-193` 靠 `if rid in HISTORY` 判定
  「这个 id 已执行过，返回缓存不能重跑」（`host.py:40-44` 注释自述这是「幂等去重用的
  key 表」）。记录被抹掉后 → **同一个 id 会真的再执行一遍**。对一个能在用户机器上跑
  PowerShell 的东西，这是最不能接受的一类 bug。
- 更糟分支：两进程同时 `open(path,"w")`（截断+写）可能交错 → JSON 解析失败 →
  `host.py:95-96` **静默返回 `{}`** → 整份历史清空，且无任何报错
  （`host.py:115` 又用 `except OSError: pass` 吞掉异常）。
- 同类模式：`ctx_summary.py:14-16` 写 `~/.webai-hands/session-summary.md` 也是 `"w"` 覆盖。

#### ② `machine.json` 首启竞争 → 两个浏览器拿到**不同** UUID（中）

```
host.py:119-137  get_machine_id(): 没文件 → uuid4() → 写盘
host.py:388      MACHINE_ID = get_machine_id()   # 全进程只赋值一次
```

- 全新机器上两个浏览器几乎同时首次连上 host → 都读不到文件 → **各生成一个 UUID**
  → 各写一次，后写覆盖；但**两个进程内存里的 MACHINE_ID 都不再变**。
- 结果：`pong.machine_id` 里 Chrome 报 A、Edge 报 B，磁盘上是 B。DESIGN §6.7 的
  「严格点名」要求块里的 `host` 等于本机 UUID，popup 面板又让用户复制那个 UUID
  → **用户复制哪一个都可能踩坑**。
- 重启后两进程都从文件读到胜者 → 自愈。属「第一次上手必撞、之后自愈」。

#### ③ 跨浏览器没有串行化（中）

`background.js:19-27` 注释写 *"host executes globally in order … one at a time"*，
靠 `hostBusy`（`background.js:25`）/ `running` / `schedQueue` 实现。
但这些状态都在 **service worker 里，一个浏览器一份** ⇒ 两个浏览器 = 两个 host 进程
= 两条命令在同一台机器、**同一个 cwd**（`host.py:35` `HOST_CWD = ~`，硬编码）上真并发跑。
「一次只跑一条 + 跨会话 5 秒宽限」在跨浏览器时完全失效。

#### ④ 重装后版本偏移（轻，但会让排查自相矛盾）

`install.py:93-96` 用 `shutil.copy2` 覆盖 `~/.webai-hands/host.py`，但**已在运行的 host
进程早已把源码读进内存**，长连接不退出就继续跑旧代码 ⇒ 重装后可能出现「Chrome 跑新版、
Edge 还跑旧版」，直到那个端口断开。

#### ⑤ `host.log` 追加写（轻，可接受）

`host.py:69` 是 `open(...,"a")`，两进程内容交错但不丢。不用管。

#### 附带发现：`sys.argv` 完全没用

Native messaging 会给 host 传第一个参数 = 调用方 origin（`chrome-extension://<id>/`）。
`host.py` 里没有任何 `sys.argv` 使用（`shell_argv` 只是同名函数）⇒ **调用方身份被丢弃**。
这本是「区分是谁在说话」的现成抓手，可在修 ③ 时用上。

#### 建议修法

| 优先级 | 改动 | 说明 |
|---|---|---|
| P0 | `save_history` 改**追加式 JSONL** | `open(...,"a")` 追加一行；读取时按 id 后者胜、裁剪 500 条 / 1MB。追加写对小消息是原子的（POSIX `O_APPEND` / Windows `FILE_APPEND_DATA`），两进程各写各的、**不再互相抹掉**，顺带消掉「一行坏 = 整份崩」。约 30 行，只动 `host.py:91-116` + 启动时裁剪 |
| P0 | `machine.json` 改**先创建者胜** | `os.open(path, os.O_CREAT\|os.O_EXCL\|os.O_WRONLY, 0o600)`；`FileExistsError` 就**回读文件用别人的值**，而不是继续用自己内存里的。保证全机器一个 UUID |
| P1 | 跨浏览器互斥：**先不做真锁** | 真锁（`fcntl.flock` / `msvcrt.locking`）会把「忙碌时立刻拒绝」改成「阻塞等锁」，要重新设计 5 秒宽限语义，风险大。先按调用方 origin 给独立 cwd，至少让相对路径不互踩；把「跨浏览器不串行」写进 DESIGN 的已知限制 |
| P2 | 重装后可察觉 host 变更 | host 在 pong 里回自身版本/哈希，扩展发现不一致就提示重启浏览器。消除 ④ 的静默失败 |

**不建议**拆成 `~/.webai-hands-chrome/` / `-edge/`：machine_id 会分叉（违反 DESIGN §6.7
「身份属于机器」），`skill/` 要维护两份，install/uninstall 复杂度翻倍。
共享目录是 **feature**，问题全在状态文件的并发处理，是能修的。

### 7.4 对本文 §一「Edge 专属待办」的三处事实纠正

#### 纠正 ① 第 2 条「不加 Edge 注册表则 Edge 连不上宿主」—— 不准确，Edge 本来会回退读 Chrome 的键

MS 官方给的 Edge 注册表查找顺序：

```
HKCU\SOFTWARE\Microsoft\Edge\NativeMessagingHosts
HKCU\SOFTWARE\Chromium\NativeMessagingHosts
HKCU\SOFTWARE\Google\Chrome\NativeMessagingHosts      ← Chrome 键就是回退项
（HKLM\SOFTWARE\ 下 WOW6432Node / 原生 各三档同理）
```

原文：*"If the registry entries for Microsoft Edge don't have the location of the native
messaging host manifest file, the Chromium and Chrome registry locations are used as
**fallback** options."*

所以 `install.py:156-158` 只写 Chrome 键，Edge **很可能已经能连上**。但同一文档紧接两句：

- *"it doesn't query the locations that are listed in the following code snippet"*
  （**只读第一个命中的位置那个 manifest**）
- *"If you have an extension both at Microsoft Edge Add-ons and the Chrome Web Store, you
  must add the extension IDs that correspond to **both** of the stores in the
  `allowed_origins`"*

⇒ **仍应显式两边都注册，都指向同一个 manifest 路径。** 理由：依赖回退太脆；企业策略
`NativeMessagingUserLevelHosts=0` 会整个禁掉用户级 host；一旦只有 Edge 键存在，会读到
过期 manifest 而静默降级。

**并且 `uninstall.py:25-30` 现在只删 Chrome 键** —— 加了 Edge 键后必须同步删，否则用户
机器上会留下指向已删除 manifest 的僵尸注册。

#### 纠正 ② 第 3 条的候选值写错了：不是 `edge-extension://`

**没有这个 scheme。** 历史上 MS 一句老文档写的是 `extension://<id>`（无 `chrome-` 前缀）。
MS **现在的** native messaging 文档明确写：

```json
"allowed_origins": ["chrome-extension://{microsoft_catalog_extension_id}"]
```

⇒ `install.py:141` 统一写 `chrome-extension://` 是**对的，不用改**。万一 Edge 真连不上
要回退，试的是 `extension://<id>/`，**不是** `edge-extension://`。
不改这一条会白费一轮。

#### 纠正 ③ `native-host/com.webai.hands.json` 是个危险的僵尸文件

内容把 `path` 写死成**开发者本机的** `D:\Users\Achilles\Workspace_01Active\Python\webai-hands\native-host\host.bat`，
`allowed_origins` 只有 2 个 ID。

- 好消息：核对 `git ls-files` 确认**未被 git 跟踪**（`.gitignore` 里明确列了
  `native-host/com.webai.hands.json`），用户克隆拿不到。
- 坏消息：它躺在工作目录里，文件名与内容看起来「像是」该被注册的那个文件。
  `install.py` 其实从不使用它（`write_manifest()` 自己生成到 `~/.webai-hands/`）。
  任何「手动把这个 json 拷进注册表」的临时排错动作都会让 host 指向开发者本机路径。
- **建议直接删除**，别留着。

### 7.5 建议落地顺序（待用户拍板）

1. **先修并发**（P0 两条，纯 `host.py`，用户无感、不动商店包）：
   JSONL 历史 + `machine.json` 原子创建。不修则任何多浏览器用户都会随机遇到重复执行。
2. **Edge 首发前定 ID 集合**：抄 CWS 的 `key` 进仓库 manifest（3→2）；试一次带 `key`
   上传 Edge；然后一次性改 `install.py`（白名单 + Edge 注册表 + 提示语）与
   `uninstall.py`（删 Edge 键）。同步修正 §7.4 的三处说法。
3. 白名单数据源化 + pong 带 host 版本号（为下一轮铺路）。

## 八、附：两个仓库的推送配置变更（2026-10-08，已实施）

> 与扩展本身无关，但与本文档自身的提交/推送流程有关，故记录。

本次会话按用户要求把 **webai-hands** 与 **FocusQuota** 两个仓库都改成
「一次 `git push` 同时推 GitHub + Gitee」：

```ini
[remote "origin"]
	url     = https://github.com/Achillesy/<repo>.git    # 只用于 fetch
	fetch   = +refs/heads/*:refs/remotes/origin/*
	pushurl = https://github.com/Achillesy/<repo>.git    # push ①
	pushurl = https://gitee.com/achillesy/<repo>.git     # push ②
```

- **顺序不能反**：实测 GitHub 在前时，若 Gitee 推失败，GitHub 那一次已推成功
  （整体 rc≠0）。若 Gitee 在前，它的失败会连累 GitHub。
- `git fetch` / `git pull` / `git fetch --all` **只走 GitHub**，不建 gitee 跟踪分支。
- FocusQuota 原有的独立 `gitee` 远端已删除（改动前已 grep 确认无脚本引用该远端名）。
- **注意**：本文档一旦 commit 并 `git push`，会**同时**进 GitHub 和 Gitee。
  若不想同步，先决定是加 `.gitignore` 还是换位置。
- 想回滚：`git config --unset-all remote.origin.pushurl`。
